# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **Repository foundation.** A TypeScript server on Node.js 24 that refuses to start without a database URL, a public URL, two different tokens of at least 32 characters each and an auth secret of at least 32 bytes, applies its database migrations on start, and answers `/healthz` when the database answers.
- **Database schema** for projects, goals, items, linked T3 threads, suppressions, comments, stage proposals, security sources, sync and job runs, Telegram updates, visits, settings, devices and the audit log, with the codes and unique keys the product rules rely on.
- **Hebrew and English labels** for every stage, item status, item type and severity.
- **Container image and Compose files**: the image runs as `node` on a read-only root file system with no capabilities; a development stack with its own PostgreSQL; a production Compose file behind Traefik.
- **Services and audit**: every write goes through a service with an explicit actor and source and writes an audit row (before and after) in the same transaction. Agents, the bot and the sync never delete and never change a stage; they propose one. Items use optimistic concurrency by version and set or clear the closing time with their status. Deleting an item or project suppresses its T3 threads or project so the sync never recreates it.
- **Secret check** for agent text: known token formats, private keys, credentials in URLs and assignments, IPv4 addresses outside documentation ranges and host names under `MIKUD_PRIVATE_DOMAINS` are refused with `secret_suspected` and the rule name; thread titles from the sync are redacted instead.
- **Start of thread** in one transaction: finds, links or creates the thread's item and sets it in progress; a retry or a race returns the same item; child threads are refused.
- **Sync apply** for T3 snapshots (projects, missing items, child-thread folding, per-item status over all linked threads, the owner wins, compare-and-set) and for security snapshots (alert counts and open Issues per repository), with per-record errors and a run record.
- **Read models**: the morning view per device (waiting on you, new since the last visit, security lines, agent updates, projects, inbox count, sync freshness), project and item detail, inbox, archive and audit log.
- **HTTP API** under `/api/v1` with bearer tokens or the owner's signed-in browser, a CSRF check for browser changes, a rate limit on failed token attempts, and stable error codes. See `docs/api.md`.
- **Browser sign-in** with Better Auth: one owner account with a username, a password and a mandatory code from an authenticator app (TOTP). The first run creates the account and sets up TOTP with a QR code and the key as text. A browser stays signed in for 30 days by default; Settings sets that length (1 to 90 days) and an optional sign-out after a time without activity, and its Account section lists the signed-in browsers, changes the password, signs out, signs out the other browsers or signs out everywhere. A page whose session ended goes to sign-in, says why, and comes back afterwards; Telegram links open after signing in. Sign-in, codes, setup and password changes are rate limited and checked against cross-site requests; every sign-in, sign-out, enrolment, password change and session end is in the activity log, and a sign-in that cannot be recorded does not happen. Locked out: `node dist/server/cli.js reset-password` on the server prints a new password once, removes TOTP and signs out every browser. Agents and the sync keep their tokens.
- **MCP server** at `/mcp` (Streamable HTTP, stateless, bearer token) with eleven tools for agents.
- **Workflow scripts and CI**: `scripts/local.sh` for the development stack, `scripts/verify.sh` with repository guards, lint, types, unit and database tests, and a container check; a CI workflow and weekly Dependabot updates.
- **Sync tool** (`dist/sync/mikud-sync.js`) for the owner's PC: runs the `overview` collector, reads every T3 project's threads through the T3 CLI, and sends the threads and each project repository's security and Issues counts to Mikud. Security data keeps the time of its last successful read, and a missing or failed source is reported as such, never as zero alerts. The agent token is never accepted on the command line, printed, or passed to a child process.
- **Reconciler prompt** (`prompts/reconcile.md`) for the T3 scheduled task that runs the sync tool every morning.
- **Telegram bot**: the owner sends plain text to the bot and it lands in the inbox, with a reply that links to the new item. Each update is recorded with its item and audit row in one transaction and acknowledged to Telegram only after that, so a repeated or redelivered update never files twice. Other chats get no answer; text that looks like a secret is refused without being repeated. Off until `MIKUD_TELEGRAM_BOT_TOKEN` and `MIKUD_TELEGRAM_CHAT_ID` are set.
- **Morning message** at 08:00 Asia/Jerusalem, Sunday to Friday: what waits on the owner (with links), how much is new since his last visit or the last message, up to two security lines, and the time of the last T3 sync when it is stale; one line when nothing needs him. Sent at most once a day: a run that may have gone out is never resent, a refused send is retried until 11:00, and a later start skips the day. Hebrew or English, from the settings.
- **Telegram status** for the owner at `GET /api/v1/telegram/status`: configured, polling, last update and the latest morning run.
- **Web UI** in Hebrew (right to left, the default) and English, light and dark, for desktop, the icon-rail width and phones: the morning view (waiting on you with stage proposals to accept or reject, new since the last visit, one security line per project with its data time, agent updates by project, projects with goal progress and open Issues, the inbox count and the last T3 sync with a banner when it is stale), all projects filtered by stage, a project (stage set by the owner with Undo, proposals, near goal, where we are, items by status, security sources, delete), an item over any page with its own address (status, type and project change at once with Undo; title, details and comments saved on purpose; linked T3 threads; history), the inbox with project and type in place, the archive and the activity log loaded as they scroll, and settings (language, date and time format, closed-item days, session length and idle sign-out, the account, this browser's theme, suppressions, sync and Telegram status). The bell counts what needs the owner on every page; quick add opens from any page with N. Pages update themselves; no Refresh button.
- **The server serves the built UI** from `dist/web` with a page fallback, a Content-Security-Policy that allows only Mikud's own scripts, styles and fonts, and long caching for hashed files. Fonts (Onest, Noto Sans Hebrew, IBM Plex Mono) and icons ship in the image; nothing loads from another site.
- **UI checks**: unit tests for the date, time and number helpers, the API client and locale keys; guard tests that fail on a popup built outside the shared builders, a page without its own refresh, or a date formatted outside the helpers; `verify.sh` checks the UI build for external assets and the development mock, and runs Playwright end-to-end tests (first-run setup with TOTP, sign-in with a code, a wrong password, sign-out, morning, an item status change with Undo, quick add) against the container on desktop and phone.
- **Agent instruction draft** (`docs/agent-instruction.md`): proposed text for the shared agent configuration and the MCP connection for Claude Code and Codex, awaiting the owner.
- **Release workflow**: a manual Release workflow on `main` (patch, minor or major) runs the whole CI, then `scripts/release.sh`: the version from `package.json`, the `Unreleased` section closed, a release commit and an annotated tag pushed together, `ghcr.io/shlomiporush/mikud:<version>` then `:latest` with provenance and an SBOM, and the GitHub Release from the changelog section. An existing tag is never moved; a run that stopped halfway is finished by the next run; `--dry-run` changes nothing. `scripts/test-release.sh` covers the refusals and the resume paths against a local remote and runs with the guards.
- **Pull request preview**: `scripts/try-pr.sh <number>|status|restore` builds a pull request's head in a disposable worktree and runs it as its own Compose project (`mikud-pr`) with its own PostgreSQL, generated tokens and auth secret, an owner with a generated password and TOTP secret, Telegram off and invented fixtures, on `127.0.0.1:8091`. It never touches the development stack.
- **Deployment notes** (`docs/deployment.md`): the database and `.env`, fitting the network behind a NetBird-only reverse proxy, first start, the first-run setup and sign-in, recovery, agents and the reconciler, the one-time move from the dry run, what to do after a restore, and upgrades.
- **Test morning message**: Settings, Telegram, "Send a test morning message" (`POST /api/v1/telegram/test-message`, owner only) sends today's morning message to the owner's chat at once, audited, without touching the 08:00 run.
- **Local settings for a dry run**: the development stack also reads an optional, ignored `.env.dev` at the repository root after `docker/dev.env`, for real tokens and the Telegram settings; `scripts/verify.sh` and `scripts/try-pr.sh` never read it.

### Fixed

- **Morning message never sent twice**: a 5xx or an answer that is not Telegram's own JSON (a gateway's error page) may hide a message that went out, so it is `unknown` and never resent; only Telegram's 4xx refusal or no connection at all is retried.
- **Owner deletes always win over the sync**: the sync checks a suppression inside the transaction that would recreate the item or project, serialized with the owner's delete by an advisory lock, so a delete during a sync run is never undone.
- **Older snapshots never roll back**: a thread record not newer than the stored activity, and security or Issues counts older than the stored ones, are ignored.
- **Incomplete T3 reads are not a fresh sync**: the sync tool sends the projects it could not read (`failedProjects`); the run is `partial`, their items are not decided, and the board's freshness comes from the last complete run, with a later partial run shown as such.
- **No query text or parameters in logs**: unexpected errors are logged as their class name, PostgreSQL SQLSTATE and error code only.
- **Secret check**: a private key block is redacted whole (to the end of the text when its END line is missing), and environment-style assignments such as `MIKUD_OWNER_TOKEN=...` or `DB_PASSWORD: ...` are caught.
- **New since your last visit stays put**: the morning page keeps its first read's boundary on every refresh and records the visit only after that read was shown, at the server's time of the read.
- **Item drafts never overwrite a change made meanwhile**: saving sends the version the typing started on; a conflict keeps the text and offers Reload.
- **Undo restores everything**: Undo after a type or project change also restores the severity or the goal that the change cleared.
- **Times in the morning message** follow the same Date Format and Time Format settings as the UI, including `h:mm a`; `browser` writes the default numeric date and the 24-hour clock.
- **Telegram status**: a failed read shows as a failure, not as an unconfigured bot.
- **Owner deletes win over child-thread folding**: folding a child thread's link onto its top-level thread and an owner delete never overlap, and a delete suppresses the thread ids it actually removes, so a deleted item is not recreated from the moved link.
- **New since your last visit never hides a slow write**: every transaction of the server ends after 30 seconds (`transaction_timeout`, so PostgreSQL 17 or newer is required), and a visit is recorded one minute before the read it marks as seen. Items written in that minute may show as new twice.
- **A failed security or Issues read never overwrites known counts**: a record without a time is ignored when the stored one has a time.
- **Partly read T3 projects**: a project whose thread list had invalid records is sent as `failedProjects`, so its items are not decided from an incomplete picture.
- **Secret check**: after an environment-style secret name, any value of 8 or more characters that is not a placeholder is caught, lower-case hex and passphrases included.
- **Security audit rows** record the Issues count that was stored, not one that was refused as older.
- **Test morning message**: a send that may have gone out (a timeout, a lost connection, a 5xx) is reported as `telegram_uncertain` with "check the chat before sending again", not as refused. The send is audited before it goes out and again with its outcome; when only the outcome cannot be recorded, the answer is still success, with a warning.
- **No deadlocks between owner deletes, thread links and the sync**: every change to thread links and suppressions (an agent starting or linking a thread, the sync's folding and creation of items and projects, the owner's deletes and removal of a suppression) takes one lock before anything else and runs one at a time, so none of them is aborted by a database deadlock.
- **The morning message never misses a write made while the previous one was sent**: "new" counts from one minute before the previous message's read, not from its send time. Items written in that minute may be counted in two messages.
