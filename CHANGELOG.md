# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **Repository foundation.** A TypeScript server on Node.js 24 that refuses to start without a database URL, a public URL and two different tokens of at least 32 characters each, applies its database migrations on start, and answers `/healthz` when the database answers.
- **Database schema** for projects, goals, items, linked T3 threads, suppressions, comments, stage proposals, security sources, sync and job runs, Telegram updates, visits, settings, devices and the audit log, with the codes and unique keys the product rules rely on.
- **Hebrew and English labels** for every stage, item status, item type and severity.
- **Container image and Compose files**: the image runs as `node` on a read-only root file system with no capabilities; a development stack with its own PostgreSQL; a production Compose file behind Traefik.
- **Services and audit**: every write goes through a service with an explicit actor and source and writes an audit row (before and after) in the same transaction. Agents, the bot and the sync never delete and never change a stage; they propose one. Items use optimistic concurrency by version and set or clear the closing time with their status. Deleting an item or project suppresses its T3 threads or project so the sync never recreates it.
- **Secret check** for agent text: known token formats, private keys, credentials in URLs and assignments, IPv4 addresses outside documentation ranges and host names under `MIKUD_PRIVATE_DOMAINS` are refused with `secret_suspected` and the rule name; thread titles from the sync are redacted instead.
- **Start of thread** in one transaction: finds, links or creates the thread's item and sets it in progress; a retry or a race returns the same item; child threads are refused.
- **Sync apply** for T3 snapshots (projects, missing items, child-thread folding, per-item status over all linked threads, the owner wins, compare-and-set) and for security snapshots (alert counts and open Issues per repository), with per-record errors and a run record.
- **Read models**: the morning view per device (waiting on you, new since the last visit, security lines, agent updates, projects, inbox count, sync freshness), project and item detail, inbox, archive and audit log.
- **HTTP API** under `/api/v1` with bearer tokens or a paired browser's cookie, a CSRF check for browser changes, a rate limit on failed token attempts, browser pairing and device management, and stable error codes. See `docs/api.md`.
- **MCP server** at `/mcp` (Streamable HTTP, stateless, bearer token) with eleven tools for agents.
- **Workflow scripts and CI**: `scripts/local.sh` for the development stack, `scripts/verify.sh` with repository guards, lint, types, unit and database tests, and a container check; a CI workflow and weekly Dependabot updates.
- **Sync tool** (`dist/sync/mikud-sync.js`) for the owner's PC: runs the `overview` collector, reads every T3 project's threads through the T3 CLI, and sends the threads and each project repository's security and Issues counts to Mikud. Security data keeps the time of its last successful read, and a missing or failed source is reported as such, never as zero alerts. The agent token is never accepted on the command line, printed, or passed to a child process.
- **Reconciler prompt** (`prompts/reconcile.md`) for the T3 scheduled task that runs the sync tool every morning.
- **Telegram bot**: the owner sends plain text to the bot and it lands in the inbox, with a reply that links to the new item. Each update is recorded with its item and audit row in one transaction and acknowledged to Telegram only after that, so a repeated or redelivered update never files twice. Other chats get no answer; text that looks like a secret is refused without being repeated. Off until `MIKUD_TELEGRAM_BOT_TOKEN` and `MIKUD_TELEGRAM_CHAT_ID` are set.
- **Morning message** at 08:00 Asia/Jerusalem, Sunday to Friday: what waits on the owner (with links), how much is new since his last visit or the last message, up to two security lines, and the time of the last T3 sync when it is stale; one line when nothing needs him. Sent at most once a day: a run that may have gone out is never resent, a refused send is retried until 11:00, and a later start skips the day. Hebrew or English, from the settings.
- **Telegram status** for the owner at `GET /api/v1/telegram/status`: configured, polling, last update and the latest morning run.
- **Agent instruction draft** (`docs/agent-instruction.md`): proposed text for the shared agent configuration and the MCP connection for Claude Code and Codex, awaiting the owner.
- **Release workflow**: a manual Release workflow on `main` (patch, minor or major) runs the whole CI, then `scripts/release.sh`: the version from `package.json`, the `Unreleased` section closed, a release commit and an annotated tag pushed together, `ghcr.io/shlomiporush/mikud:<version>` then `:latest` with provenance and an SBOM, and the GitHub Release from the changelog section. An existing tag is never moved; a run that stopped halfway is finished by the next run; `--dry-run` changes nothing. `scripts/test-release.sh` covers the refusals and the resume paths against a local remote and runs with the guards.
- **Pull request preview**: `scripts/try-pr.sh <number>|status|restore` builds a pull request's head in a disposable worktree and runs it as its own Compose project (`mikud-pr`) with its own PostgreSQL, generated tokens, Telegram off and invented fixtures, on `127.0.0.1:8091`. It never touches the development stack.
- **Deployment notes** (`docs/deployment.md`): the database and `.env`, fitting the network behind a NetBird-only reverse proxy, first start, pairing, agents and the reconciler, the one-time move from the dry run, what to do after a restore, and upgrades.
