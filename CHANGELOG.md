# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **Server**: a TypeScript server on Node.js 26 that refuses to start without a database URL, a public URL and its versioned keys (`MIKUD_AUTH_SECRETS` for sign-in, `MIKUD_SETTINGS_KEYS` for secrets stored in Settings), or with a `BETTER_AUTH_*` variable set. It applies its database migrations on start, logs a failed migration with PostgreSQL's message, and answers `/healthz` when the database answers. Needs PostgreSQL 17 or newer: every transaction ends after 30 seconds (`transaction_timeout`). Unexpected errors are logged as their class, SQLSTATE and error code only, never with query text or parameters.
- **Container image and Compose files**: one image, run as `node` on a read-only root file system with no capabilities; a production Compose file behind Traefik with the database outside it (`MIKUD_TRUSTED_PROXIES` names the proxy); a development stack with its own PostgreSQL, which also reads an optional, ignored `.env.dev` for real keys.
- **Projects, goals and items** with Hebrew and English labels for every stage, item status, type and severity. Every write goes through a service and writes an audit row in the same transaction. Agents, the bot and the sync never delete and never change a stage; they propose one. Items use optimistic concurrency by version. Deleting an item or project suppresses its T3 threads or project, so the sync never recreates it.
- **Secret check** for text from agents and the bot: known token formats, private keys (redacted whole), credentials in URLs, environment-style secret assignments, IPv4 addresses outside documentation ranges and the private domains from Settings are refused with `secret_suspected`; thread titles from the sync are redacted instead.
- **Start of thread** in one transaction: finds, links or creates the thread's item and sets it in progress; a retry or a race returns the same item; child threads are refused.
- **Sync** from the owner's PC: the sync tool (`dist/sync/mikud-sync.js`, Node.js 24) runs the `overview` collector, reads every T3 project's threads through the T3 CLI, and sends them with each repository's security alert and open Issues counts. The server applies a snapshot per record, the owner always wins (a delete during a sync run is never undone), older records and counts never replace newer ones, and a failed read never overwrites known counts. Projects that could not be read fully are reported as such: the run is partial, their items are not decided, and the board's freshness comes from the last complete run. The agent key is never accepted on the command line, printed or passed to a child process. `prompts/reconcile.md` is the prompt of the T3 scheduled task that runs it every morning.
- **HTTP API** under `/api/v1` and an **MCP server** at `/mcp` (Streamable HTTP, stateless) with eleven tools. Agents and the sync use agent keys (`mkd_` and 64 letters, stored hashed), each approved by the owner in the browser; the browser uses the owner's session. Browser changes need a CSRF header, failed keys are rate limited, and errors carry stable codes. See `docs/api.md`.
- **Sign-in** with Better Auth: one owner account with a username, a password and a mandatory authenticator app (TOTP); the authenticator app shows the username. The first run creates the account, sets up the authenticator with a QR code or the key as text, and shows 10 backup codes once (copy, download, "I saved them"). Sign-in takes an authenticator code or a backup code, or, when the owner turns it on in Settings, a code sent to the owner's Telegram chat. A browser is signed out after 30 days without Mikud open (1 to 90 in Settings); background updates never extend a session. Settings, Account lists the signed-in browsers, changes the password, makes new backup codes, sets up a new authenticator, and signs out the others or all; this browser signs out from the account menu, which asks about unsaved changes first and keeps them when the sign-out fails. Sign-in is rate limited and checked against cross-site requests, and every sign-in, sign-out, enrolment and password change is in the activity log. Locked out: `node dist/server/cli.js reset-password` on the server prints a new password once and signs out every browser; two-factor stays.
- **Agent approval in the browser**: `node dist/sync/mikud-sync.js connect --name <name> --for <sync|claude|codex>` asks Mikud for a code and opens `/connect/device`, where the owner, signed in with two-factor, compares the code and allows or denies. The command then gets one key with that name, ending after `--days` (1 to 365, default 90), and ends its temporary session at once. `--for sync` writes the key to the sync's env file, readable by the owner only; `--for claude` adds Mikud to Claude Code itself with `claude mcp add` at user scope, replacing an older `mikud` entry; `--for codex` sets `MIKUD_AGENT_KEY` (with `setx` on Windows, in an owner-only `~/.config/mikud/codex.env` elsewhere) and adds Mikud with `codex mcp add`. When `claude` or `codex` is missing or fails, it prints that setup once instead. Settings, Agent access shows the commands, lists each agent with its end date and last request, and disconnects one or all at once; there is no button that creates a key. Settings, Account names a leftover `mikud connect` session and signs out any single session. Approvals, denials, keys and ended sessions are in the activity log. Built on Better Auth's device authorization, bearer and api-key plugins.
- **Telegram bot**: the owner sends plain text to the bot and it lands in the inbox, with a reply that links to the new item. A repeated or redelivered update never files twice. Other chats get no answer; text that looks like a secret is refused without being repeated. On when a bot token (stored encrypted) and a chat id are set in Settings.
- **Morning message** at 08:00 Asia/Jerusalem, Sunday to Friday: what waits on the owner (with links), what is new since the last visit or the last message, up to two security lines, and the last T3 sync when it is stale; one line when nothing needs the owner. Times follow the Date Format and Time Format settings, in Hebrew or English. Sent at most once a day: a send that may have gone out is never resent, a refused one is retried until 11:00, and a later start skips the day. Settings, Telegram shows the bot's status and sends a test morning message at once without touching the 08:00 run.
- **Web UI** in Hebrew (right to left, the default) and English, light and dark, for desktop, the icon-rail width and phones: the morning view (waiting on you with stage proposals to accept or reject, new since the last visit, security lines, agent updates, projects with goal progress and open Issues, the inbox count and the last T3 sync), all projects by stage, a project (stage set by the owner with Undo, proposals, goals, items by status, security sources, delete), an item over any page with its own address (status, type and project with Undo; title, details and comments saved on purpose, never over a change made meanwhile; linked T3 threads; history), the inbox, the archive and the activity log, and Settings (language, date and time format, closed-item days, Account, Agent access, Telegram, the secret check's private domains, suppressions, sync status). A setting that an environment variable sets is shown locked with the variable's name. The frame: a top bar with the logo and the page title, the page's main action beside it (on a phone, on the title's line), quick add and the bell; a sidebar that folds into an icon rail (Ctrl+B) and stays folded after a reload; a card with the last T3 sync; an account menu with the theme (light, dark or the system's) and sign-out; on a phone a bottom tab bar with every other page under More. The bell counts what needs the owner; quick add opens from any page with N; pages update themselves. Fonts and icons ship in the image, and the Content-Security-Policy allows only Mikud's own files.
- **Workflow scripts and CI**: `scripts/local.sh` for the development stack; `scripts/verify.sh` with repository guards, lint, types, unit and database tests, the image with its health, user and hardening checks, and Playwright end-to-end tests on desktop and phone; `scripts/try-pr.sh` to run a pull request as its own stack with invented data on `127.0.0.1:8091`; a CI workflow and weekly Dependabot updates.
- **Release workflow**: a manual Release workflow on `main` (patch, minor or major, and `dry_run` to check everything and publish nothing). It reuses the newest CI run of the commit on `main` when its latest attempt succeeded, waiting up to 30 minutes for one that still runs; otherwise it runs the whole CI itself (`scripts/ci-result.sh`). A reused run is checked again right before publishing, and the release stops if a newer run appeared. Then `scripts/release.sh`: the `Unreleased` section closed, a release commit and an annotated tag pushed together, `ghcr.io/shlomiporush/mikud:<version>` then `:latest` with provenance and an SBOM, and the GitHub Release from the changelog section. An existing tag is never moved, and a run that stopped halfway is finished by the next run. `scripts/test-release.sh`, `scripts/test-ci-result.sh` and `scripts/test-release-workflow.sh` run with the guards.
- **Documentation**: deployment notes (`docs/deployment.md`) and a draft of the agent instructions and MCP connection for Claude Code and Codex (`docs/agent-instruction.md`), awaiting the owner.
